# 🚀 Harisa Deployment Guide

В этом документе описан процесс деплоя приложения (**Vercel**) и базы данных (**Supabase**).

## 1. Деплой Frontend-части (Next.js на Vercel)

Harisa App хостится на платформе **Vercel** на тарифе **Hobby**. Деплой происходит автоматически через интеграцию с GitHub.

### Основной флоу:
1. Вы вносите изменения в код фронтенда локально (`harisa-app/src/...`).
2. Сохраняете изменения и коммитите их в git.
3. Делаете `git push` в ветку `master` репозитория `taulujas-png/Harisa`.
4. Vercel ловит вебхук от GitHub и автоматически начинает сборку (Build) и деплой (Deployment). Процесс занимает ~1-2 минуты.

3. Снятие полного дампа базы данных (Audit & Backup)

Для глубокого аудита структуры, проверки всех колонок, связей (FK), триггеров и функций используется скрипт полного дампа. Это позволяет ИИ-ассистенту видеть реальную картину БД, а не гадать по старым миграциям.

### Как снять полный дамп:
1.  **Настройте подключение:** Убедитесь, что в корне проекта (или в `admin_scripts/`) есть файл `db_config.json` с данными **Transaction Pooler (IPv4)**:
    ```json
    {
      "host": "aws-0-eu-central-1.pooler.supabase.com",
      "port": 6543,
      "database": "postgres",
      "user": "postgres.oavmddmynugdpoetfyjv",
      "password": "ВАШ_ПАРОЛЬ_ОТ_БД",
      "ssl": "require"
    }
    ```
2.  **Запустите скрипт дампа:**
    ```bash
    cd Harisa
    node admin_scripts/full_db_dump.js
    ```
3.  **Результат:** В корне проекта обновится файл `FULL_DB_DUMP.json`. Этот файл содержит:
    *   Все таблицы и их колонки (с типами данных).
    *   Все перечисления (Enums).
    *   Все внешние ключи (Foreign Keys) и индексы.
    *   Все SQL-функции (RPC) и триггеры.
    *   Все политики безопасности (RLS).

> **ВАЖНО:** Если вы добавили новую колонку через `npx supabase migration`, обязательно запустите дамп заново, чтобы ИИ видел актуальную схему.

## 4. Возможные проблемы (Troubleshooting)

*   **Ошибка: Deployment Blocked (Hobby teams do not support collaboration)**
    *   *Причина:* Vercel на тарифе Hobby блокирует деплой, если email гит-коммита не совпадает с email'ом владельца привязанного GitHub аккаунта. (Такое случается, если перенести проект на другой компьютер, или если ИИ-ассистент сделает коммит от лица сгенерированной почты типа `developer@harisa.edu`).
    *   *Решение:*
        1. Проверьте ваш локальный email командой: `git config user.email`. Он **обязательно** должен совпадать с вашей почтой, привязанной к GitHub (`taulu.jas@gmail.com`).
        2. Если почта не совпадает, перенастройте локальный git:
           ```bash
           git config user.email "taulu.jas@gmail.com"
           git config user.name "taulujas"
           ```
        3. Если ошибочный коммит уже отправлен (и заблокирован), перепишите его автора и отправьте форсом:
           ```bash
           git commit --amend --reset-author --no-edit
           git push origin master --force
           ```
           *После этого Vercel увидит "правильного" автора и запустит деплой.*
*   **Ручной деплой (альтернатива GitHub):** Если интеграция с GitHub сломалась, всегда можно задеплоить проект напрямую из терминала с помощью Vercel CLI:
    ```bash
    cd harisa-app
    npx vercel --prod --yes
    ```
*   **Ошибка: Couldn't find any `pages` or `app` directory**
    *   *Причина:* Vercel пытается собрать Next.js прямо в корне гит-репозитория, а сам код приложения лежит в папке `harisa-app`.
    *   *Решение:* Перейдите в настройки Vercel → **Settings** → **General** → **Root Directory**, впишите туда `harisa-app` и нажмите Save. После этого перезапустите деплой (Redeploy).

## 2. Деплой Backend-части (Supabase & БД)

Все схемы базы данных, таблицы, функции (RPC) и триггеры хранятся в папке `supabase/migrations/` в виде `.sql` файлов.

### Как применить изменения к продакшн-БД:
1. Создайте новую миграцию (если вы внесли изменения вручную или через ИИ):
   ```bash
   npx supabase migration new name_of_migration
   ```
2. Напишите/вставьте SQL код в созданный файл.
3. Отправьте (запушьте) миграцию на удаленный сервер Supabase:
   ```bash
   npx supabase db push --yes
   ```
4. Если Supabase ругается, что миграция "устаревшая" по времени (например, вы создали её локально позже, чем другую миграцию в продакшене), используйте флаг `--include-all`:
   ```bash
   npx supabase db push --yes --include-all
   ```

*После успешного выполнения команды, новые колонки и функции мгновенно станут доступны для фронтенда через REST API Supabase.*
